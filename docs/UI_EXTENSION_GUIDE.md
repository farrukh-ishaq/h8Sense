# UI Extension Guide

The UI is currently centered in `src/main/java/com/islamophobia/detector/ui/MainView.java`.

## What exists today

`MainView` contains:
- a header
- summary cards
- a category filter
- a `Grid<ContentAnalysis>`
- a detail panel
- feedback buttons

Because this is Vaadin, the UI is Java code, not React/Vue.

## Most common extension points

### 1. Add a new summary card

Edit `createSummaryCards()` and `updateDashboardStats()`.

Example ideas:
- total live feed items
- analyses by provider
- fallback-analysis count
- last feed fetch time

### 2. Add a new column to the grid

Edit `createViolationsGrid()`.

Good columns:
- `modelUsed`
- source URL domain
- feedback totals
- whether the row was generated by fallback mode

### 3. Improve the detail panel

Edit `showDetails()`.

Good improvements:
- show raw model response in a collapsible panel
- render links to Quran or Hadith sources
- show metadata from `ContentItem.metadata`
- show badges for category and confidence

### 4. Add a new page

Create another Vaadin route:
```java
@Route("feeds")
@PageTitle("Feed Explorer")
public class FeedExplorerView extends VerticalLayout {
}
```

Good pages to add:
- feed explorer
- prompt lab
- model diagnostics
- feedback review page

## Suggested first UI exercises

### Exercise A: Show source domain
In `createViolationsGrid()`, add a derived column from `sourceUrl`.

### Exercise B: Add a “copy raw response” button
Use a small button in the detail panel for fast debugging.

### Exercise C: Add a filter for analysis status
Support:
- confirmed violations
- non-violations
- fallback analyses

### Exercise D: Show live pipeline health
Use actuator or service methods to surface:
- pending content count
- processed URL count
- whether backfill is enabled

## UI design guidance for this repo

- keep server-side logic in services, not in the view
- avoid large monolithic methods in `MainView`
- when the UI grows, split it into reusable helpers/components
- prefer explicit labels over icons only
- expose operator diagnostics when AI is degraded

## When to create a reusable component

Extract a component when:
- the same layout pattern repeats twice
- a panel has its own state or event flow
- you want to test or reuse a widget across multiple routes

Examples:
- `AnalysisSummaryCard`
- `AnalysisDetailPanel`
- `FeedbackToolbar`
- `PipelineStatusBanner`

## Backend/UI contract tips

Before adding UI features, confirm whether the needed data already exists in:
- `ContentAnalysis`
- `ContentItem`
- `ContentAnalysisService`
- `ContentAnalysisController`

If not, add the backend data shape first, then render it in Vaadin.

## High-value UI improvements for this project

1. add a banner when the app is in mock/fallback mode
2. add a page for raw ingested content, not only confirmed violations
3. add manual feed refresh controls for operators
4. add charts from Prometheus or cached service stats
5. add onboarding tips directly in the UI for new developers
